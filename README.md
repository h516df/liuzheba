# 留着吧（原拾藏）

Android 本地私人档案应用。人物与物品共用一种结构：只有称呼也能建档，照片、视频和自定义资料以后再补。

[下载正式版](https://github.com/h516df/liuzheba/releases/latest) · [提交问题](https://github.com/h516df/liuzheba/issues)

从旧版本升级请下载正式 APK **覆盖安装，不要卸载**；本地资料会保留。v0.5 起检查、下载更新无需 GitHub 登录。

## 功能

- **发现**：直接以沉浸式全屏回看照片、视频和文字；上下刷不同档案、左右切换同一档案的媒体，当前视频默认静音自动播放。
- **档案**：列表与封面可切换；搜索名称、正文、分类、标签和字段内容。
- **资料与编辑**：完整页面、空白字段、删除撤销、只保存结构的字段模板和安全网页链接。
- **媒体**：导入后保存原件副本；发现页视频自动静音播放，手动播放的查看器仍由用户控制，离开或进入后台停止。
- **本地管理**：明暗主题、皮肤、草稿、回收站、完整备份恢复、应用锁和检查更新入口。

不提供云同步、自动抓图、人脸识别或资料上传服务。系统选择器导入的个人资料由使用者自行管理。

## 从源码构建

需要 JDK 21、Android SDK 36 和 SDK Build Tools 36.0.0。安装 Android Studio 后配置本地 `local.properties` 或 `ANDROID_HOME`，接受 Android SDK 许可。

```sh
./gradlew testDebugUnitTest assembleDebug
```

Windows 使用 `gradlew.bat`。调试安装包位于 `app/build/outputs/apk/debug/app-debug.apk`，构建不需要正式签名或 GitHub 令牌。依赖版本固定在 Gradle 文件中，首次构建需要联网下载依赖。

正式包自行签名，参考 [发布与签名](docs/RELEASING.md)。自行编译的调试包使用不同签名，不能直接覆盖官方正式包；不要为安装调试包卸载存有资料的正式版。

## 测试

JVM 与 Compose 宿主测试覆盖档案编解码、搜索、随机浏览、模板、链接与旧备份兼容。原生测试覆盖持久化、备份、编辑/保存/重开、照片、视频及应用锁。

```sh
./gradlew --init-script tools/verification.init.gradle assembleDebug assembleDebugAndroidTest
```

以上配置给调试包附加 `.verification` 后缀，原生 UI 用例仅允许在这个独立包中运行。使用专用模拟器安装两个调试 APK 后执行：

```sh
adb -s <your-emulator> shell am instrument -w dev.h516.shicang.verification.test/androidx.test.runner.AndroidJUnitRunner
```

人像测试图片已替换为可重现的几何色块；测试视频为无真实人物的合成测试内容。正式新安装不含示例人物、测试照片或测试视频。

## 数据与限制

最低 Android 7.0 / API24。SQLite schema1，备份 format6 保存混合媒体、文字、作者与搜索规则，读取旧格式1–5。备份包含私人资料且未加密，请自行选择安全的保存位置；应用锁不等于备份加密。

0.22 沿用0.16–0.21的本地资料结构与备份格式。更新资料从本项目公开 Release 匿名读取，不上传私人资料。模拟器和自动测试不能证明所有手机、大尺寸媒体或系统关联跳转均兼容。fork 后应配置自己的更新地址和包名，详见发布文档。

## 0.13 媒体收录

发现页上下跟手切换档案，左右浏览媒体；照片放大和视频操作保留。查看器可保存或分享原件，媒体列表支持多选。

首页右上角「链接下载」接受 HTTPS 媒体直链及 yt-dlp 支持的作品页面。解析在手机本地运行，图集可勾选；系统负责后台下载，完成后从下载记录选择新建/已有档案收录并保存。可直接从其他 App 分享图片、视频到留着吧。下载记录不包含在档案备份内；切换恢复资料后不会自动把旧任务写入新资料。

平台的登录、验证、链接有效期与接口变化会影响解析。可在内置网页中完成验证后重试，或使用平台/其他下载器取得媒体再分享到留着吧。个人主页和直播链接仍可保存为资料，不承诺自动批量抓取主页或录制直播。

解析组件为固定版本 Chaquopy 17.0.0 + Python 3.12 + yt-dlp 2026.10.26；首次源码构建还需要 Python 3.12（可用 `SHICANG_BUILD_PYTHON` 指定可执行文件）。本版原生运行时包含 arm64-v8a 和 x86_64，需要 64 位设备、Android 7.0 及以上；APK 仍使用原包名和正式签名覆盖升级。

离线解析适配测试：安装固定版本 `yt-dlp==2026.10.26` 后执行 `python tools/tests/test_media_bridge.py`，全部使用合成图集/格式元数据。

## 0.17 档案与沉浸浏览重构

一份档案可同时保存正文、照片和横竖视频。详情先阅读正文再浏览混合媒体；编辑时统一保存，返回自动留草稿。媒体可筛选、拖动排序、设封面和多选移除。0.17底部为「档案 / 发现」，设置从齿轮进入。

沉浸浏览保留视频完整比例，支持手动横屏、进度恢复和不中断位置的文字阅读。导入结果持久记录，中断重试避免重复收录。实现范围、来源、自动检查与设备边界见 [重构记录](docs/REBUILD.md)。正式安装包只从 [GitHub Releases](https://github.com/h516df/liuzheba/releases/latest) 下载；候选源码或调试构建不代表正式发行已完成。

## 0.18 连贯的档案体验

发现（左）与档案（右）共用卡片、阅读和沉浸查看器。发现展示整份收藏并包含纯文字档案；档案保留搜索、筛选和列表/封面切换。阅读入口一致，沉浸按钮独立，完整浏览可上下换档案、左右换媒体。详情集中编辑入口并提示未保存草稿；编辑中移除全部媒体也可撤销。问题审查、取舍及验收边界见[产品体验改进](docs/PRODUCT_REWORK.md)。正式发行状态以Release及HANDOFF为准。

## 0.19 日常操作优化

「添加」直接展示新建档案、相册、拍照、保存链接和下载链接媒体，减少多级菜单；档案页把排序与高级搜索分开。只有一份档案时不显示无效的换序，底部双标签和设置入口更加清楚；编辑返回后明确提示草稿尚未更新正式档案。保留0.18的统一阅读和媒体浏览能力，0.17可跳过0.18直接覆盖升级到0.19（需正式原签名发布包）。发布之前版本候选不能覆盖已有正式版，具体状态以Release及HANDOFF为准。

## 0.20 发现与档案分工、社媒链接收录

发现页不再堆档案卡片：直接上下滑动切换档案，左右滑动切换同一档案的照片与视频；视频在当前发现页自动静音播放，纯文字也可以单独展示，阅读和编辑沿用同一份本地档案。底部可进入档案页继续搜索、筛选、管理，发现页的管理按钮不占主要画面。

社媒链接下载覆盖更多小红书短链（包括 xhslink.cn）和图集字段；完成内置网页验证后，可回传当前作品地址并重新解析。抖音图集仍使用既有适配器，其他社媒的视频由固定的 yt-dlp 处理；不把 HLS/DASH 分片或网页封面冒充可直接下载的媒体。下载错误区分过期、权限、请求频率及存储问题。部分作品受平台权限、访问区域和接口变化影响，不能保证所有链接均可下载。

## 0.22 混刷珍藏和作者档案（2026-10-31）

- **发现页默认混刷**：照片和视频按适合展示的作品穿插呈现；小红书图集作为同一组左右浏览。类型和已有档案分类只是可选筛选，不会移动原档案里的资料。
- **自动作者档案**：收录的小红书、抖音作品若有可靠的平台作者 ID，可自动建立/复用作者卡，并从「档案 → 作者」集中查看珍藏；只凭昵称不合并。
- **链接兼容与缺失提醒**：部分可信小红书短链在 `/404` 跳转仍保留笔记 ID 时尝试恢复作品地址；本地原件缺失时可返回原档案。平台权限、作者限制、登录状态仍会使某些实际链接无法下载。
