# 留着吧：收录与页面重构

用户在了解项目和外部参考后要求开始实施，并强调：使用逻辑有问题、步骤太多、不够简洁、UI/UX不够苹果。此前暂停的本地试改已恢复，继续使用设计 PR #31 的任务分支。首批围绕实际收录流程和代表页面落地，后续增强按本记录接续。

## 当前批次

| 路径 | 原行为 | 本批行为 |
| --- | --- | --- |
| 首页收录照片/拍照 | 先新建编辑，再进入媒体操作 | 收录面板直接打开系统选择器；取消不创建空草稿；选中后选择新建或已有档案 |
| 详情追加媒体 | 打开整份编辑，导入后还需保存 | 原子追加到正式档案；若已有草稿，同时追加媒体，保留其未提交字段 |
| 编辑添加媒体 | 添加按钮后再弹相册/拍照选择框 | 两个直接可见的动作 |
| 下载图集 | 逐项选目标、进入编辑和保存 | 同一来源的待收录媒体可一次选择目标；部分失败只标记成功项，保留失败项和临时源供重试 |
| 新建收录 | 草稿与正式保存的文案混杂 | 新建仍先形成持久草稿，明确保存后完成收录；下载记录可继续打开对应新草稿 |
| 内容入口 | 笔记、作者藏在导入图标下 | 档案区提供档案/笔记/作者索引，分别保存轻量页面状态 |
| 日常首页 | 搜索选项、排序等同时显示 | 搜索、内容和收录优先；高级搜索与排序放在显示菜单，资料管理集中在我的 |

直接追加和取消边界优先复用并审查 PR #28 的 `importIntoArchive` / AppModel 对齐逻辑，不整体合并其版本、发版、自动保护调度和其他未合并任务。原有媒体检查、原件副本、旧备份读取与原包名沿用。导入复制和关联仍有 Store 的串行边界，不宣称大文件导入时无限并发。

## 视觉与复用

读取 Orchard UI 0.3，来源 `h516df/orchard-ui@5da1e128bf5f4cb9ad48b2adb1aa060d91047eb2`：README、组件目录、Apple视觉与页面参考、UX模式、接入说明、Compose控件/页面源码以及设置/备忘录实际合成预览。

Orchard 保持私有，留着吧是 Apache-2.0 公开仓库。本批根据已读的视觉与行为规范独立编写产品控件，不提交 Orchard 私有源码、生成文件、AAR或预览图片，也不让公开构建依赖私有库访问。新的 `GalleryChrome` 属于留着吧自身代码，统一按压反馈、搜索/输入、分段、导航、确认与按钮；媒体解码、存储和系统权限由原项目负责。现阶段导航材质是实色，不标作实时模糊或完整 Liquid Glass。

中性浅底、蓝色动作、大标题、连续分段、分组内容、持续输入标签和完整选中导航用于表达层级；深色、长内容和大字号要实际渲染核对。Android系统栏、返回、键盘和文件选择器保持平台行为。原有主题与外观设置入口保留。

## 发现页：苹果式媒体浏览（用户后续反馈）

用户查看实际发现页后再次明确“苹果风”。本次沿 PR #31 接续，采用已读 Orchard 0.3 的导航、文字层级与边缘工具规则，并参考其记录的 Apple HIG Materials / Tab bars 页面；没有复制私有组件源码或 Apple 图片、字体、图标。

- 媒体延伸至发现页浮动导航背后，取消原先底部浅色整块背景。三入口保持可见，导航缩小内边距、减轻选中底色；发现页使用深色材质，其他页面按现有浅深主题。
- 顶部张数独立居中，资料/更多为圆形动作，保留至少48dp触控区。工具仍按原规则自动隐藏，辅助功能触摸探索下保持可用。
- 底部档案名与“查看档案”明确分层；点击直接打开完整详情，少一次资料面板中转。顶部资料按钮仍可打开简要资料，菜单中的原功能继续保留。
- 视频画面同样延伸到底部；播放进度工具另留导航高度，避免被底栏遮挡。此处只改布局，不更改播放意图、静音、倍速或后台生命周期逻辑。
- 空库使用深色媒体画布与清楚的回档案入口。保留上下换档案、左右换媒体与返回原媒体的状态。

当前使用带透明度的表面与细边框，没有新增实时背景采样/模糊，不称为完整 Liquid Glass。预览是Compose/Robolectric API35原生图形宿主的合成媒体渲染，不能代替实体手机、编解码或动画性能验收。实际通过数量与源树见HANDOFF本次接续记录。
