# 0.18 产品体验改进

用户在0.17发布后指出界面割裂、交互与功能像demo，明确发现应在左、档案在右。本轮以已发布应用之后的main 6d2f53750f9b4a7e45140e6be9d2a216e261e357为基线，保留既有数据与工作成果，不合并过时PR。

## 审查与改动

| 原问题 | 实际调整 | 验收方式 |
| --- | --- | --- |
| 发现直接进入纯黑媒体流，档案使用资料管理页面 | 根页面共用主题、导航和ArchiveStoryCard，发现用大卡、档案用紧凑卡；两个入口进入同一个详情 | 同一合成档案跨页面原生宿主截图；浅深色/200%字号 |
| 纯文字档案被发现排除 | 发现包含全部未删除正式档案，文本与名称可独立阅读 | 通过实际创建/保存/发现/阅读，确认没有新草稿 |
| 封面与标题操作含义不稳定 | 封面和正文打开档案；独立媒体按钮进入统一沉浸查看器 | 卡片点击区域分开；大字号回归防误触 |
| 同一档案散落“编辑文字/整理/编辑”等入口 | 集中一个编辑入口；添加/回收站在明确选项菜单 | 保存、取消、草稿重开、直接追加各自回归 |
| 详情白卡和操作数量盖过内容 | 阅读排版、完整封面、正文、媒体目录；来源与补充资料逐步展开 | 有/无正文、有/无媒体及大字号截图 |
| 编辑移除媒体后只能放弃全部编辑来恢复 | 草稿内撤销媒体移除，保留正文；全部移除后按钮仍可见 | 移除全部→撤销→保存→重读SQLite及原件 |
| 浏览→文字→编辑→返回状态分散 | 两根共用ArchiveFeed/FullPhotoFrame，saveable holder保留查看器；首项尊重用户点选 | 同一媒体位置、文本阅读、编辑返回；原生视频解码/暂停/旋转专项 |
| 缺失或无法解码的预览看起来像空白 | 明确“原件不可用/预览不可用”，不删除档案或原件记录 | 合成缺失文件检查；仍可操作与备份恢复 |

这不是用户已认可的最终视觉设计。测试只能证明具体行为和渲染可达，不能证明所有设备手感或用户审美满意。

## 参考与取舍

- [Ente 2025设计迭代](https://ente.com/blog/building-the-best-photos-app/)和[2026查看器](https://ente.photos/blog/crafting-the-best-photos-app/)：采用管理界面与查看器的渐进信息层级；完整照片/视频保持独立沉浸画布。没有复制其代码、图标、照片或宣传素材。
- [Day One多视图](https://dayoneapp.com/guides/tips-and-tutorials/journal-views-in-day-one-for-ios/)与[混合媒体](https://dayoneapp.com/guides/getting-started-with-day-one/adding-media-in-day-one/)：同一记录可以有不同密度的浏览方式，文字与媒体属于同一档案。本轮保留一份档案正文和有序混合媒体，不擅自添加富文本块迁移。
- [mymind](https://mymind.com/)：重新发现自己的收藏；不采用其AI自动整理、云服务或删除式随机回顾。
- [Apple iOS26官方说明](https://www.apple.com/newsroom/2025/06/apple-elevates-the-iphone-experience-with-ios-26/)：明确区分资料浏览入口，统一控件规则。没有模仿Liquid Glass或宣称实时模糊。

以上官方页面及相关图片已在本轮调研实际查看；有年份的示例仅作为对应版本证据。保留原生Kotlin/Compose、Coil、Media3、Telephoto，依赖许可沿原第三方声明，不引入私有UI源码。

## 功能边界与后续

本轮优先完成主流程一致性、纯文字发现、草稿提示与媒体撤销。现有导入事务、失败重试、备份、视频编辑和作者功能继续使用原实现并做相关回归；不宣称本轮把所有功能重写或优化完毕。长按拖动仍受可见网格范围限制，前移/后移可用于可访问排序；大库性能与不同手机手感仍需后续实际设备观察。下载平台变化不在本轮承诺范围。

发布遵守原证书、code递增、旧数据保留与原件摘要校验。0.17资产和标签不覆盖。宿主、原生模拟器、正式系统覆盖升级与物理手机分别记录。实际执行结果保存在HANDOFF及docs/acceptance/v0.18，不预写通过。
