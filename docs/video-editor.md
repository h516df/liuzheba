# 直播录屏画面编辑（首切片）

真实入口：全屏视频 → 更多 → 编辑视频。框选保留画面或一个固定黑色遮挡区域，选择时间范围，切换效果预览，另存到原档案。原视频不被覆盖，声音默认保留，作者、标签与档案资料不改变。

## 取舍与依据

复用 Media3 1.11.1 同版本的 Transformer / Effect / ExoPlayer，不引入 FFmpegKit 或额外的视频编辑框架。官方 `Crop` 和 `OverlayEffect` 既用于预览，也用于导出；所有选区以旋转后直立画面的左上角归一化坐标存储，先遮挡再裁剪。输出为 H.264/AAC 的 MP4，设备可能不支持某些输入格式/HDR/编码组合，失败时原件保留。

- Android 官方编辑应用教程：https://developer.android.com/media/implement/editing-app
- 官方导出、取消和线程要求：https://developer.android.com/media/media3/transformer/getting-started
- 官方 Crop 坐标：https://developer.android.com/reference/androidx/media3/effect/Crop
- 官方 GitHub demo（Apache 2.0）：https://github.com/androidx/media/tree/1.11.1/demos/transformer

黑色遮挡适合固定按钮；不能还原被弹幕遮住的真实内容，不是 AI 去物、移动目标跟踪或局部模糊。当前保留单个连续片段、单个遮挡区域，后续按实际需求扩展。最大输入边长 4096，单个导出副本沿用统一 6GB（6,000,000,000字节）上限。长录屏建议先截取有用片段。大文件流式与空间边界见 [6GB 视频说明](large-media.md)。

## 数据和生命周期

导出仅写本次随机 cache 临时文件；播放预览在导出前释放，避免两套硬件解码器争用。前台导出显示进度，可取消；离开应用停止导出，不声称后台完成。最后入库阶段不可取消，验证并追加独立媒体，事务提交与状态刷新完整执行。取消或失败只清理本次新文件；从不修改原片。

入库时重新核对当前 library generation、活动档案、原媒体摘要和现存路径，有未保存草稿则拒绝。使用当前档案追加，而不是用打开编辑器时的快照覆盖作者或备注。新副本沿用现有自动保护与备份索引。

## 验证边界

单元测试覆盖裁剪坐标、时间与选区边界；Robolectric 存储测试用合成元数据验证另存、关联、草稿拒绝、原片不变与数据库失败回滚。Compose 测试验证框选/模式切换/大字号/返回，并不代替真实编解码。

必须在设备另验：90°/270°录屏旋转、裁剪叠加遮挡输出像素、音画同步、长录屏空间不足与取消、低端设备编码、切后台/锁屏、独立副本的自动保护和相册导出。不得将宿主合成截图或元数据 shadow 当成真实导出成功。

精确时间输入提供起始/结束秒（可含小数），避免长录屏只能靠滑块粗略截取；范围外、非数字和不足 0.25 秒均明确拒绝。
