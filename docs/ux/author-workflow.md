# 作者主页与档案工作流

## 用户可走的路径

1. 档案首页浏览紧凑的媒体卡或文字卡；搜索高级选项默认收起。
2. 打开档案，从媒体区直接添加照片/视频，进入同一份档案的编辑页。
3. 编辑顺序保持媒体、作者、来源、分类标签、其他资料。保存提交；取消需确认；返回可保留草稿或放弃。保存失败不关闭编辑页。
4. 首页“导入与作者”入口进入作者卡，或在档案编辑页选择“关联作者”。粘贴四平台主页，读取公开资料，核对后确认保存。
5. 已有作者可手动添加其他平台；同名不合并。可关联到多个档案，各平台按钮打开对应的 HTTPS 主页，没有对应 App 时由系统浏览器处理。

## 数据与安全边界

- Author、PlatformIdentity 使用独立稳定 UUID；Archive.authorIds 保存关联。
- nickname、publicAccount、platformId、idType、profileUrl 不混用。微博 UID、个性域名和 screen_name 路由明确区分，不把 UID 标成微号。
- 资料格式 5，读取 1–4 版本时作者为空；备份、外部保护、恢复和撤销恢复均使用同一完整 Library 编码。
- 导入只接受精确白名单主机、HTTPS 与默认端口，不接受凭据、任意子域、私有 scheme。短链域名不直接证明作者身份。
- 请求不使用浏览器或系统登录状态、Cookie、认证头、代理、验证码绕过或收费接口。每次重定向都重新校验；DNS 校验结果直接交给 HTTP 客户端使用，阻止重新解析到私网。
- 最多四次请求、单次五秒、整体约十二秒，页面上限 512 KiB；只读 HTML，最多二十个 JSON 脚本，每个 256 KiB、深度二十、访问五千节点。不执行 JavaScript。
- 只有匹配当前主页标识的结构化资料可补公开账号；冲突留空。OG 标题仅为待核对的昵称候选。登录页、空壳或访问失败时仍可保存本地可验证的主页，缺失资料留空。
- 用户明确点击后才发起 ACTION_VIEW。不能保证平台 App 一定接管，也不使用任意 intent scheme。

## 验证范围

普通测试全部使用合成数据，不访问真实平台、不使用私人账号。AuthorProfilesTest 覆盖路由、身份、恶意地址与大小/深度边界；AuthorStoreTest 覆盖作者关联和完整备份/恢复/撤销；AuthorWorkflowSnapshotTest 为实际 Compose 渲染与确认/取消交互；ArchiveWorkflowUiTest 为隔离原生包交互。

真实平台匿名资料提取成功率、实体手机平台 App 接管和正式同签名覆盖升级须单独验收。没有运行的阶段不能由截图或测试数量替代。

## 后续而非本次范围

“我的视图”、更细的模板/布局个性化仍属后续，不为此增加首页复杂设置。首版不做通用爬虫、自动合并作者、账号登录、云同步或外部图片抓取。
