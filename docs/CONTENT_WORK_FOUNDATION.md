## 当前分支首批实现

1. `Archive.work` 是可选的结构化外部作品信息（平台、作品 ID、来源 URL、原文、预期媒体数）；旧对象没有该字段则保持原样，备份 `format6` 向前读取兼容。没有来源字段的私人档案仍是用户自己的内容，**不根据昵称/链接字段猜测或迁移**。
2. Python 解析器传递真实提取器作品 ID 与完整正文（最大 10 万字；超限明确失败），小红书/抖音图集也传原文，Kotlin 侧不再只收标题。来源和正文进入下载记录的独立批次元数据，避免每个文件重复保存长正文。
3. 下载批次有独立 ID 和顺序；新作品保存时自动创建正式内容和完整正文笔记，无须再手工新建档案或保存草稿。初步按同平台作品 ID（不具备 ID 时只按完全一致来源 URL）找到同一作品，重复下载同样文件使用 SHA-256+长度+MIME 阻止重复媒体副本；失败的媒体仍留在任务记录。
4. 作品正文和来源参加本地搜索；原有作者精确 ID 归集沿用，昵称不参与匹配。普通个人媒体导入不改变，不启用内容哈希去重。
5. 哔哩哔哩视频作者只在 yt-dlp 返回**数值型 MID** 时自动关联 `space.bilibili.com/{mid}`；Instagram 作者必须由提取器给出数值型 PK，用户名只作显示和主页跳转，改名后保留原作者归集。仅凭主页用户名不会自动创建身份。快手作者的可靠 ID 方案仍待验证。
6. 无法确认平台的网站必须用完全相同来源 URL 判断是否同一篇作品，不能仅凭碰巧相同的 ID 合并；元数据索引损坏时保留原下载任务日志，不把未保存的媒体隐藏。
7. 点击“下载并保存”自动解析、入系统下载队列，批次结束后后台自动将成功媒体归为作品；失败项留在队列供手动重新解析。也可点“先预览”选择部分媒体。
8. Instagram 图文适配仅在上游明确标记为图片的条目提取原始图片版本，视频无法取得时不把封面误收为原件。我的页使用双列作品墙和二级笔记/作者菜单；切换视频缓冲期间保留海报层。这些界面仍需进一步视觉完善与设备确认。

## 安全边界

- 原备份格式、包名、签名配置、现有原件位置不变；新增字段仅对新作品生效。保存过程先将媒体复制/关联到可恢复草稿，再提交正式作品和正文笔记。复制失败不删除下载来源，提交失败保留草稿以便恢复。
- 下载原始长文只在一个批次元数据项持久化，任务结束后记录清理才移除；不能把每张图的元信息分别当一篇作品。个人账号会话、Cookie 不持久写入作品元信息。
